# Ответы на вопросы по Практической работе №7: Вёрстка и валидация форм

1. **Какие HTML5-атрибуты используются для клиентской валидации и какую функциональность они предоставляют?**
   - `required`: указывает, что поле обязательно для заполнения.
   - `minlength` / `maxlength`: задают лимиты на минимальное/максимальное количество вводимых символов.
   - `min` / `max`: определяют диапазон допустимых значений для чисел или дат.
   - `pattern`: принимает регулярное выражение, которому должен строго соответствовать вводимый текст.
   - `type` (например, `type="email"` или `type="url"`): включают автоматическую встроенную валидацию формата.

2. **В чем разница между novalidate атрибутом формы и отключением валидации через JavaScript?**
   Атрибут `novalidate` отключает только стандартные, дефолтные всплывающие окна браузера при ошибках, но сохраняет работу нативного API (интерфейса `ValidityState` у полей), позволяя разработчикам перехватить логику и написать собственную кастомную обработку на JavaScript. Отключение через JS обычно означает полную отмену проверок или очистку обработчиков событий `submit`.

3. **Как правильно связать <label> с полем ввода и почему это важно для доступности?**
   Связать можно двумя способами: обернуть поле ввода внутрь тега `<label>` или использовать атрибут `for` у тега `<label>`, значение которого должно идеально совпадать с идентификатором `id` нужного инпута. Это критически важно для доступности (Accessibility), так как программы-экранные дикторы (скринридеры) зачитывают подпись при переходе на поле, а обычные пользователи получают возможность кликать по тексту лейбла для фокусировки инпута.

4. **Какие типы полей input наиболее подходят для разных видов данных?**
   - `type="email"` — для почтовых адресов (вызывает клавиатуру с символом `@` на смартфонах).
   - `type="tel"` — для телефонных номеров (открывает цифровую панель ввода).
   - `type="password"` — скрывает вводимые символы точками ради безопасности.
   - `type="date"` — вызывает удобный нативный графический календарь.

5. **Как работает валидация с помощью pattern атрибута и в каких случаях его следует использовать?**
   Атрибут `pattern` проверяет значение поля на соответствие регулярному выражению (RegEx). Браузер не позволит отправить форму, если текст не подходит под маску. Его следует использовать для специфических типов данных, формат которых строго регламентирован, но не проверяется нативно (например, серия и номер паспорта, почтовый индекс, номера телефонов по маске страны).

6. **Какие события JavaScript используются для реализации валидации в реальном времени и почему?**
   - `blur`: срабатывает, когда пользователь уводит фокус с поля. Идеально подходит для первичного вывода ошибки, чтобы не раздражать человека предупреждениями в процессе набора текста.
   - `input`: срабатывает при каждом нажатии клавиши или изменении текста. Используется для моментального скрытия сообщения об ошибке, как только пользователь начал исправлять опечатку.

7. **Как обеспечить доступность сообщений об ошибках для пользователей скринридеров?**
   Для этого контейнерам текстовых ошибок добавляют атрибут `aria-live="assertive"` или связывают инпут со спаном ошибки с помощью атрибута `aria-describedby="ID_элемента_ошибки"`. В таком случае скринридер моментально зачитает текст появившейся ошибки, как только поле потеряет фокус.

8. **В чем преимущества использования fieldset и legend для группировки полей формы?**
   Тег `<fieldset>` логически и визуально объединяет связанные по смыслу поля (например, блок «Пароли» или «Контакты»), а `<legend>` задает этой группе понятный заголовок. Для скринридеров это создает контекст: при переходе к первому полю группы программа сначала зачитает название всего блока, помогая незрячим пользователям ориентироваться.

9. **Как реализовать кастомную валидацию для сложных случаев (например, подтверждение пароля)?**
   Для этого используют JavaScript. При вводе данных или отправке формы вычисляются значения обоих полей. Скрипт проверяет условие `password.value === confirmPassword.value`. Если они не равны, с помощью метода `setCustomValidity('Текст ошибки')` или ручного добавления класса ошибки полю присваивается невалидное состояние, а отправка формы блокируется через `e.preventDefault()`.

10. **Какие методы CSS используются для визуального отображения состояний валидности/невалидности полей?**
    Используются встроенные псевдоклассы `:valid` и `:invalid`, часто в связке с псевдоклассами `:focus` или `:placeholder-shown` (чтобы пустые поля до начала ввода не подсвечивались красным). Также применяется добавление кастомных классов (например, `.error`) методами JavaScript, что дает более гибкий контроль над моментом отображения стилей.
