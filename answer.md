  Ответы на вопросы для самоконтроля

1. Три основные области работы:
     Рабочая папка – место, где файлы создаются и изменяются.
     Индекс – зона временного хранения (черновик коммита).
     Репозиторий – база данных, где хранятся все сохраненные версии (коммиты).
    Примечание: При работе через сайт GitHub эти этапы объединяются в один клик по кнопке "Commit changes".

2. **Что происходит при выполнении команд:
    `git add` – файлы переносятся из рабочей папки в индекс (черновик).
    `git commit` – изменения из индекса навсегда сохраняются в историю репозитория на компьютере.
    `git push` – сохраненная история отправляется с компьютера на сайт GitHub.

3. Зачем писать информативные сообщения:
   Чтобы в будущем вы или другие разработчики могли сразу понять, какие именно изменения были сделаны в конкретном "сохранении", не просматривая весь код заново.

4. Отличие `git add имя_файла` от `git add .`:
    `git add имя_файла` добавляет в индекс только один конкретный указанный файл.
    `git add .` добавляет сразу все новые и измененные файлы в текущей папке.
    Первое лучше использовать для точечных правок, второе – когда нужно сохранить много изменений разом.

5. Что показывает `git status`:
   Она показывает состояние файлов: какие из них новые, какие изменены, а какие уже готовы к сохранению (находятся в индексе). На разных этапах её вывод меняется, подсвечивая файлы красным (не сохранены) или зеленым (в индексе) цветом.

6. Зачем нужна `git remote add origin URL`:
   Она связывает локальную папку проекта на компьютере с удаленным репозиторием в облаке GitHub. Слово "origin" – это стандартное имя (псевдоним) для этого удаленного сервера.

7. Зачем нужен флаг `-u`:
   Он используется при самой первой отправке (`git push`), чтобы связать локальную ветку с удаленной. В будущем это позволяет отправлять код короткой командой `git push` без указания адреса.

8. Ветка по умолчанию:
   Сейчас на GitHub веткой по умолчанию создается `main`. Это важно, так как это главная ветка проекта, в которой находится стабильная и рабочая версия программы, готовая к показу.

9. Как просмотреть историю коммитов:
   В терминале – командой `git log`. На сайте GitHub – нажав на вкладку "Commits" (иконка часов). Там виден автор коммита, дата, уникальный код (хэш) и сообщение.

10. Если сделать изменения, но не выполнить `git add` перед `git commit`:
    Коммит не запишет эти изменения в историю. Git просто сообщит, что сохранять нечего, так как черновик (индекс) пуст.
